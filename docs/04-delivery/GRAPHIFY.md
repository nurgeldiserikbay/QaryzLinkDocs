# Graphify қолдану тәртібі

Күйі: қосымша developer құралы; жобаға runtime dependency ретінде қосылмаған және осы репозиторийлер үшін әлі іске қосылмаған.

## Қай кезде пайдалы

- Claude немесе Codex жаңа модульді зерттегенде файлдар арасындағы байланысты табу.
- Өзгеріс алдында шақырулар мен тәуелділіктерді қарап шығу.
- Backend, Front, Admin үлкейгенде модуль шекараларын түсіну.
- Refactoring кезінде ықтимал әсер ететін кодты анықтау.

Қазір backend шағын: күнделікті жұмысқа файл іздеу мен IDE navigation жеткілікті. Graphify-ды маңызды refactoring алдында қолдануға болады. Ол ESLint, TypeScript, тест, code review немесе Docs-та бекітілген бизнес сызбаларын алмастырмайды. NestJS dependency injection және динамикалық байланыстарды бастапқы кодтан қосымша тексеру керек.

## Алғашқы қауіпсіз іске қосу

Python developer ортасында:

```bash
uv tool install graphifyy
graphify --version
graphify extract ./src --code-only --no-cluster
```

Команданы QaryzLinkBack түбірінен орындау керек. Алдымен тек src каталогы талданады. graphify-out және graph.json генерацияланған файлдарын git-ке қоспау керек. Қолданылған Graphify нұсқасын және backend commit SHA-ны талдау есебінде көрсету қажет: ескі graph жаңа кодтың дәлелі болмайды.

Code-only режимі AST талдауын қолданады және ресми құжаттама бойынша LLM API кілтін қажет етпейді. Docs/PDF/image семантикалық талдауы бөлек LLM backend қолданады; ол автоматты түрде қосылмайды. Нақты пайдаланушы құжаттарын, production dump, .env, secret немесе жеке мәліметтерді индекстеуге болмайды.

## Қарапайым жұмыс тәртібі

1. Жаңартылатын модульдің graph-ын жасау.
2. Байланысты файлдарды анықтау, олардың кодын тікелей оқу.
3. Күтілетін мінез-құлық тестін жазу және оның өтпейтінін тексеру.
4. Кодты өзгертіп, typecheck, lint, test және build орындау.
5. Маңызды архитектура өзгерсе, canonical Docs диаграммасын қолмен жаңарту.

Graphify байланыстары EXTRACTED және INFERRED деп ажыратылуы мүмкін; inferred байланыс тексеруді қажет етеді. Graph-та байланыс болмауы оның кодта жоқ екенін дәлелдемейді.
